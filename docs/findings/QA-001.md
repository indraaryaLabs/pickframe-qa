# QA-001: Unknown URLs show the "gallery could not load" error

|            |                                            |
| ---------- | ------------------------------------------ |
| Severity   | Major                                      |
| Area       | Routing, error handling                    |
| Status     | Open                                       |
| Tracked by | `tests/e2e/known-defects.spec.ts` (QA-001) |

## Steps to reproduce

1. Open any path that does not exist, for example `/does-not-exist`.

## Expected

A not-found page that says the address does not exist and links back to the home page. The HTTP status for a SPA fallback is 200, so the page itself must carry the message.

## Actual

The SPA falls through to the client-gallery view and renders the heading "Galeri belum dapat dimuat" ("The gallery could not be loaded"). A visitor who mistypes a URL is told a gallery failed, which points them at the wrong problem.

## Suggested fix

Add an explicit `*` route that renders a not-found view. Keep the gallery error for `/g/:token` only.
