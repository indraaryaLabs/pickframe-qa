# QA-008: Public pages scroll sideways on small phones

|            |                                                  |
| ---------- | ------------------------------------------------ |
| Severity   | Minor                                            |
| Area       | Responsive layout, WCAG 1.4.10 Reflow            |
| Status     | Open                                             |
| Tracked by | `tests/e2e/responsive.spec.ts` (`knownOverflow`) |

## Actual

Measured with reduced motion and web fonts loaded, so the numbers do not depend on animation timing:

| Page       | Viewport | Document width | Widest element                     |
| ---------- | -------- | -------------- | ---------------------------------- |
| `/pricing` | 360px    | 385px          | plan comparison `table` (`w-full`) |
| `/pricing` | 320px    | 385px          | plan comparison `table`            |
| `/guide`   | 320px    | 359px          | header actions (`div.ml-auto`)     |

360px is the most common Android width, so the pricing table affects real visitors. At 390px and above every page fits, and `/`, `/privacy`, `/terms` and the sign-in pages fit at every width.

Note: without reduced motion, `/pricing` at 390px and `/guide` at 360px also overflowed on one CI run, because entrance animations park content off-screen. That is a measurement artifact, so the suite now measures with reduced motion.

## Suggested fix

Find the element that sets the minimum width (the pricing comparison table and the header action group) and let it wrap or scroll inside its own container.
